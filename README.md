# Pliik Workstation for Termux

A development workstation for Android devices running Termux.

## Features

- Installs Termux dependencies.
- Boots Ubuntu 24.04 proot when needed.
- Installs Docker and Docker Compose in the proot environment.
- Clones the Pliik repository.
- Clones VS-CODE-IN-TERMUX as reference.
- Deploys Code Server using Docker Compose.
- Provides start, stop and status commands.

## Requirements

- Android device.
- Termux.
- Termux package manager access (`pkg`) to install `proot-distro` when needed.
- Ubuntu 24.04 proot; the installer creates or reuses it and installs Docker and Docker Compose dependencies with `apt`.
- Internet connection.
- Sufficient storage and RAM.
- GitHub authentication if Pliik is private.

## Quick installation

Run inside Termux:

    curl -fsSL https://raw.githubusercontent.com/mutualendemic/pliik/main/install-pliik-workstation.sh | bash

The installer checks that OpenSSL can report its version and generate a 24-byte hexadecimal value before using it for the Code Server password.

The Docker Compose path replaces the old QEMU helper flow. The container stack is started directly with Docker Compose instead of booting a VM and forwarding ports through termux-qemu-docker.

## Access

Open:

    http://127.0.0.1:8080

The installer generates a random password stored in `.env`.

View it with:

    grep '^CODE_SERVER_PASSWORD=' .env

## Management

    ~/bin-dev-start
    ~/bin-dev-stop
    ~/bin-dev-status

## Emergency Docker reset

If the Docker stack hangs or the Compose environment is stale, reset the local stack and retry:

    docker compose -f "$HOME/.config/pliik-workstation/docker-compose.yml" down
    docker compose -f "$HOME/.config/pliik-workstation/docker-compose.yml" up -d

The installer no longer depends on the QEMU helper or the stale guest-profile reset flow.

## OpenSSL troubleshooting

To print the OpenSSL diagnostics without installing packages or starting the workstation, download the current installer and run its diagnostic mode:

    curl -fsSL https://raw.githubusercontent.com/mutualendemic/pliik/main/install-pliik-workstation.sh -o "$HOME/install-pliik-workstation.sh"
    bash "$HOME/install-pliik-workstation.sh" --diagnose-openssl

The output includes the script path, Termux prefix, package status, OpenSSL search paths, version checks, and random-generation status. It reports the random output length but never prints the generated bytes. Exit code `0` means a candidate passed; `1` means none passed.

Termux separates the OpenSSL libraries from the CLI executable. If the diagnostic reports that `openssl` is installed but its binary is missing, install both packages and rerun:

    pkg install -y openssl openssl-tool
    hash -r
    bash "$HOME/install-pliik-workstation.sh" --diagnose-openssl

Share the diagnostic output if the check still fails; never share `~/.config/pliik-workstation/.env` or its password.

## Security

- Never commit `.env`.
- Never embed GitHub tokens in scripts.
- Use `gh auth login` for private repository access.
- Keep Code Server bound to localhost.

## Important

The Pliik application container is optional and requires a valid Dockerfile and confirmed application port.
